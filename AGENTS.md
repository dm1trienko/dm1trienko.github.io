# AGENTS.md

Этот файл — «правила игры» для тех, кто помогает поддерживать репозиторий (люди/боты/ассистенты).

## 1) Архитектура проекта

- Проект **без сборки**: чистый HTML+CSS+JS.
- Хостинг: **GitHub Pages**.
- Данные хранятся в `content/*.json`.
- Просмотр документов реализован в `viewer.html` + `assets/js/viewer.js`.

Главный принцип: **любой вклад должен быть возможен через PR** и проверяем на GitHub Actions (`tools/validate_content.mjs`).

## 2) Правила изменений

1. Не добавлять серверные зависимости.
2. Держать единый стиль: использовать CSS‑переменные (`--bg`, `--text`, …) и не «хардкодить» цвета.
3. Любой iframe/встраивание должно подстраиваться под тему сайта (dark/light) по возможности.
4. Все внешние ссылки — только через безопасные схемы (`https://`, `mailto:` и т.д.).
5. Не выводить пользователю «технические подсказки» в интерфейсе. Технические детали — в README/CONTRIBUTING.

## 3) Добавление контента

- Материалы: `content/resources.json`
- Расписания: `content/schedules.json`
- Опросы: `content/polls.json`
- Калькуляторы: `content/calculators/index.json` + `content/calculators/*.json` (каждый калькулятор отдельным файлом)

При добавлении карточек:
- `id` должен быть уникальным и стабильным.
- `title` — человекочитаемый.
- `semester/subject/folder/tags` — для каталогизации.

## 4) Проверка локально

Самый простой способ:

```bash
python -m http.server 8000
# открыть http://localhost:8000
```

Проверь минимум:
- вкладки переключаются
- поиск выдаёт результаты
- viewer открывает PDF/XLSX/CSV
- тема переключается и сохраняется
- меню «бургер» читабельно

## 5) Нейминг и структура файлов

- Папки: `1_семестр/`, `2_семестр/`, …
- Избегать лишних пробелов и экзотических символов в именах (лучше `_` и `-`).
- Для больших файлов — подумать о Git LFS (по необходимости).

## 6) Роли и доступ

Статический сайт не может ограничивать доступ по логину.
Ограничение делается через GitHub:
- права на запись только доверенным
- остальным — Issues/PR

Роли/описания обновляются в `content/community.json`.
